# GH-01 API pilot boundary plan

> Execute one API/security slice. Preserve all pre-existing dirty work.

**Goal:** Enforce user-selected GH-01 scope on browser and signed-agent APIs.
**Design:** `docs/superpowers/specs/2026-10-28-gh01-api-scope-design.md`.
**Feature card:** `docs/feature-cards/2026-10-28-gh01-api-scope.md`.

## Files and responsibility

- `lib/greenhouse-scope.ts`: shared fixed pilot check and stable 403 response.
- `lib/server/agent-registry.ts`: reject off-pilot agent greenhouse before D1.
- `lib/server/inspection-images.ts`: enforce scope after parse/record lookup,
  before D1 side effects or Storage calls.
- `app/api/**/route.ts`: enforce scope on browser routes with greenhouse IDs;
  filter opaque sensor config lookup to GH-01.
- `tests/greenhouse-scope.test.ts`: allow GH-01, deny other/malformed scope.
- Feature/API docs: record 403 contract and limitations.

## Steps

1. Add focused unit cases for GH-01 allow, foreign ID denial, and stable error
   response; run test and confirm expected red.
2. Add the shared helper, then apply it to all caller routes: sensors, plants,
   device points/assignments/policy, commands, image listing, image creation
   and completion, signed-agent registration paths, and opaque sensor config.
3. Run targeted scope/image tests, file-scoped lint, `npx tsc --noEmit`, build,
   and `git diff --check`; report existing typecheck failures by name.
4. Review final diff against feature card and verify no user changes were
   overwritten; no deploy, migration, or relay action.
